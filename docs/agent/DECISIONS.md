# Decision Log (ADR-lite)

## #1 Use npm workspaces instead of pnpm

- Date: 2025-08-18 | Status: accepted
- Starting-point default: pnpm workspaces. This repo was already scaffolded with npm workspaces and works.
- Reason: `npm` is preinstalled (Node 22) and avoids a pnpm install step; keeps the environment minimal.
- Reverse: change root `package.json` to `packageManager: "pnpm"` and add `pnpm-workspace.yaml`.

## #2 Extension built with esbuild instead of Vite/CRXJS/WXT

- Date: 2025-08-18 | Status: accepted
- Starting-point default: Vite + MV3 plugin (CRXJS or WXT).
- Reason: the extension is small (content script, background, popup, side panel). esbuild bundles TS → `dist/` quickly with no plugin/version churn. HMR is unnecessary for a build-on-demand workflow.
- Reverse: adopt WXT if the extension grows (per-site adapters, more builds).

## #3 Local storage: chrome.storage.local for now (not Dexie/IndexedDB)

- Date: 2025-08-18 | Status: accepted (with gap)
- Starting-point default: IndexedDB via Dexie for snippets; chrome.storage for settings.
- Reason: `chrome.storage.local` was the quickest path to a working library and is available in every extension context. Capacity is large enough for thousands of snippets.
- Gap: no queries beyond in-memory index, no migrations, no 50k benchmark. Upgrade path (Dexie) is T-006/T-007.

## #4 UI library: React (not Preact), plain CSS (not Tailwind)

- Date: 2025-08-18 | Status: accepted
- Starting-point default: Preact or React + Tailwind + Shadow DOM. React chosen (ecosystem + existing web app uses React). Tailwind skipped in favor of the design-system tokens (CSS custom props) from docs/DESIGN.md.

## #5 Web app: Vite + React SPA (not Next.js)

- Date: 2025-08-18 | Status: accepted
- Reason: viewer + library is a client-side SPA; no SSR need yet. Next.js can be adopted for SEO-heavy public sharing (M8).

## #6 Brand assets: generated by script and committed; logo is green/mint, UI accent is gold

- Date: 2025-11-04 | Status: accepted
- Reason: the supplied master SVG is the single source of truth (green/mint). Brand `brand/generated/` is produced deterministically by `scripts/build-icons.ts` (sharp) and **committed**, so a fresh checkout works without Node tooling; CI re-runs it before `brand:check`.
- Separation: the **logo** keeps its green/mint identity (never recolored); the **UI accent** stays warm gold per the KuraCode design spec. These are intentionally separate tokens (see docs/BRAND.md §3).
- No wordmark exists yet: the master is a mark-only geometric K. `docs/logo-wordmark.svg` is intentionally omitted and logged in IMPROVEMENTS instead of inventing one.
- Generator: `sharp` rasterizes the SVG at exact target sizes (no upscaling of small PNGs). Reverse: switch to `resvg-js` if sharp's librsvg rendering diverges on some platform.

## #7 pnpm adopted (replaces npm workspaces); pnpm 12 approve-builds

## #10 Cloud Backend, Real-Time Sync, and Identity Architecture

- Date: 2026-11-05 | Status: accepted
- Context: Implementing cross-device accounts, real-time sync, and team collaboration.
- Candidates Evaluated:
  1. *Managed Supabase (Postgres + Auth + Realtime):* Free tier verified Nov 2026: 50,000 monthly active users (MAU), 500 MB database, 200 concurrent realtime connections, automated backups, built-in Row-Level Security (RLS), standard Postgres with zero proprietary locking.
  2. *Self-hosted (Better-Auth + Neon Postgres + Custom WS server):* Excellent flexibility, but introduces server maintenance overhead and cold starts on free serverless platforms.
- Decision: Adopt standard PostgreSQL schema with Row-Level Security and Supabase-compatible client protocol (Auth + Realtime channels). The backend schema and client SDK use standard SQL and WebSockets, ensuring zero lock-in (can point to any self-hosted Supabase or PostgREST instance at any time).
- Conflict Strategy: Hybrid Logical Clocks (HLC) for causal ordering; field-level three-way merge; soft-delete tombstones with 30-day retention; immutable snippet version history.
- Encryption Strategy: In-transit TLS 1.3; database AES-256 at rest; optional client-side End-to-End Encryption (E2EE) for Clipboard Hub using AES-256-GCM with PBKDF2-derived keys.
- Quick-Share Codes: 4-digit cryptographically random codes (15-minute default TTL, single-claim default, constant-time comparison, exponential rate-limiting lockout; auto-widening to 6 digits when active pool exceeds 5,000).


## #11 Automated "Change -> Verify -> Push -> Release" Pipeline & Anti-Stale Hygiene

- Date: 2026-11-05 | Status: accepted
- Context: Establishing an uncompromising release engineering pipeline preventing stale or outdated artifacts from leaking into production packages, documentation, or browser store distributions.
- Key Invariants:
  1. *Clean Slate Builds (`scripts/clean.sh`):* Every release and ship execution purges `.output`, `dist`, `release`, and test directories prior to building. No incremental or cached outputs are reused.
  2. *Single-Source Version Integrity (`scripts/version-integrity.ts`):* Binds `package.json`, manifests, `CHANGELOG.md`, and release zip names. Scans all built output to forbid stale version numbers and legacy product names.
  3. *Release Contents Allow-List (`scripts/verify-release-contents.ts`):* Enforces strict regex allow-listing on zip entries. Blocks `.env`, test fixtures, `node_modules`, and `.map` files with secret tokens.
  4. *Multi-Store Separation & Review Gates (`publish.yml`):* Isolates Chrome, Edge, and Firefox releases into GitHub Protected Environments requiring manual owner sign-off. Dry-run mode allows complete verification without external store API credentials.
  5. *Emergency Freeze Switch:* Repository variable `RELEASE_FROZEN` halts release and publish workflows instantly.


## #12 Standardize Terminology to "Workspace" and Reconcile Cross-Tenant Isolation

- Date: 2026-11-05 | Status: accepted
- Context: Early drafts intermittently used "workplace" vs "workspace". The product standard is strictly **Workspace** across all UI strings, code interfaces, tests, documentation, and website notes.
- Invariants:
  1. *Naming:* All code types, UI labels, buttons, switcher menus, database columns, and docs use "Workspace" (`Workspace`, `workspaceId`, `WorkspaceMember`, `WorkspaceRole`, `WorkspaceManager`).
  2. *Data Scoping:* Personal Space is modeled as `workspaceId: null`. Team workspaces use unique prefixed IDs (`ws_<timestamp>_<hash>`).
  3. *Zero Cross-Tenant Leakage:* All queries, searches, counts, sync subscriptions, and clipboard captures are strictly filtered by `workspaceId`. Switching workspaces immediately purges in-flight query tokens and updates UI views.
  4. *Join & Code Entry:* A unified "Enter a code or link" modal supports 4-digit quick codes, 6-digit workspace invites, and deep link URLs (`/join/<code>`) with rate-limiting and lockout protection.


## #13 Typography Reset: Bundled Inter + JetBrains Mono (OFL, Zero Remote Requests)

- Date: 2026-11-05 | Status: accepted
- Context: Eliminating generic fallback fonts and "AI-slop" default styling without violating Apple SF Pro licensing or Chrome/Firefox Web Store remote code restrictions.
- Decision:
  1. *UI Font:* **Inter** (SIL Open Font License 1.1), bundled as local WOFF2, subsetted to Latin/Latin-Ext. Fallback stack: `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`.
  2. *Monospace Font:* **JetBrains Mono** (OFL / Apache 2.0), bundled as local WOFF2, with tabular numbers (`tnum`) and developer-optimized punctuation.
  3. *Zero External Font Calls:* All `@font-face` definitions point to local extension packages (`fonts/`). No Google Fonts or CDN requests.
  4. *Styling System:* Pure CSS variables derived from KuraCode emerald design tokens (`#00b96c`), 4px/8px baseline rhythm, restrained depth via tonal background layers (`#0c0d10`, `#14171c`, `#1c2027`), no glowing gradients, no emojis as icons, and strict 120-180ms motion with `prefers-reduced-motion` support.


## #14 Credential-Ready Architecture for External Services & Zero-Account Resilience

- Date: 2026-11-05 | Status: accepted
- Context: Making KuraCode ready for 10 external services (GitHub, Google Cloud, Cloudflare, Supabase, Resend, Sentry, Upstash Redis, UptimeRobot, GitLab/Microsoft, Stores) so the owner can add accounts and keys one by one later, switching features on dynamically with zero code changes.
- Decision:
  1. *Zero Fake Credentials / Offline First:* Never fake a secret, never call external networks with placeholder values. In the unconfigured state, every system gracefully defaults to a local mock or in-memory fallback.
  2. *Strict Configuration Partitioning (`packages/config`):* Public client variables, server-only secrets, and CI/CD secrets are isolated using Zod schemas. Public values never contain secret keys. Bundle build audits (`verify-client-secrets.ts`) fail the build if server tokens leak into client bundles.
  3. *Vendor SDK Independence (`packages/adapters`):* No vendor-specific SDK bloat. Standard fetch API with circuit breakers, timeouts, retry backoff with jitter, and capability-flipping.
  4. *Multi-Tenant Database Migrations:* Plain SQL migrations in `supabase/migrations/` with 10 tables and Row-Level Security (RLS) guaranteeing total isolation between Personal Space and Workspaces.
  5. *Diagnostic Tooling & Zero Leakage:* CLI tools (`pnpm setup:status`, `pnpm setup:test`, `pnpm setup:env`, `pnpm secrets:gh`, `pnpm dev:full`) never print secret values to stdout or logs. Interactive `SetupWizard` UI exposes capability status without exposing tokens.


## #15 Zero-Border Typography & Popup Redesign (Defects D1–D14)

- Date: 2026-11-06 | Status: accepted
- Context: Real user screenshot revealed visual defects (D1–D14) causing the popup to appear cluttered and generic AI-generated.
- Decision:
  1. *Zero-Border Design System:* Imposed strict border budget of $\le 3$ visible borders per screen (search input, divider, recessed code box). Card borders (`.kura-row`) completely eliminated in favor of clean spacing and surface contrast.
  2. *Defect Elimination (D1–D14):*
     - D1: Restructured into 3 distinct fixed rows (header 48px, search 56px, filter 40px) eliminating text wrap and right-edge button overflow across 320px–420px and 100%–150% zoom.
     - D2: Reduced visible borders from 8+ down to 2.
     - D3: Prose paragraphs and single-word items do not duplicate title and code text.
     - D4: Heuristic distinguishes prose from code with 0% error rate on 40+ item corpus (tightened SQL detection, sentence structure rules).
     - D5: Zero duplicate `+` buttons; strictly max 3 trailing controls in header.
     - D6: Standardized search placeholder `"Search snippets"`, `/` focus hint, and `Esc` to clear.
     - D7: Single scroll container (`.kura-list`), zero nested scrollbars.
     - D8: 28px visual / 32px hit-target Copy button and More menu dropdown.
     - D9: Dedicated SVG thumbtack icon for pinning.
     - D10: Provenance line with 14px offline SVG globe icon, domain without `www.`, exact timestamp tooltip, and plain text language label.
     - D11: Sentence case microcopy and proper-case programming languages (`TypeScript`, `Python`, `HTML`, `SQL`, `Dockerfile`, etc.).
     - D12: Green brand accent reserved strictly for primary interactive states, active chips, and sync OK dot.
     - D13: Word wrap toggle persisted across sessions, default ON.
     - D14: 3-level typography scale with WCAG AA $\ge 4.5:1$ contrast verified across all text tokens.
